# DoctorWeb1 (DW-1): оценка AI-assisted происхождения электронных писем

Студенческий проект НГУ по кейсу компании «Доктор Веб» (ТЗ DW-1 v5).
Прототип аналитического модуля: на вход письмо EML (или каталог), на выход JSON с итоговым индексом
AI-генерации, вердиктом, вероятностями по зонам письма, выделенными сгенерированными фрагментами
(символьные границы), оценками изображений и объяснением на русском языке для аналитика SOC.

> Результаты носят рекомендательный характер (п. 3.2 ТЗ). Все цифры ниже воспроизводятся командами
> из раздела «Воспроизведение» и сохраняются в `results/`. Ограничения перечислены отдельно: читайте их вместе с метриками.

## Архитектура

Конвейер по п. 4.1.12 ТЗ: **разбор → признаки → оценка → объяснение → сериализация**, плюс отдельный контур
подготовки данных, обучения и оценки качества.

```
L0  Источники      EML/каталог/архив кейса · открытые корпуса (Enron, LLMTrace) · локальная LLM (Ollama, OpenAI API)
L1  Разбор         src/eml_parser.py (MIME, HTML, изображения) · src/html_analyzer.py (видимый/скрытый текст, ссылки)
                   зоны: тема / приветствие / основной текст / подпись · src/datagen/* (генерация и разбиение датасета)
L2  Признаки,      src/detectors/feature_model.py — TF-IDF-модель предложений + стилометрическая модель документа
    модели         src/detectors/lm_model.py      — TNC-DBGC* (mDeBERTa-v3 + BiGRU + CRF), комбинированный метод
                   src/signals.py                 — маскировка (скрытый текст, zero-width, подмена ссылок), утечка промпта
                   src/image_analyzer.py          — детектор сгенерированных изображений, EXIF/C2PA, OCR, QR
L3  Результат      src/pipeline.py — индекс, вердикт, зоны с символьными границами, объяснение, JSON
L4  Интерфейсы     cli.py (prepare-data, generate, build-dataset, train, evaluate, analyze, batch) · Python API · Docker · app.py
L5  Оценка         src/evaluation/ — метрики табл. 3, бутстреп, сценарии маскировки, отчёты JSON/MD/PNG, журналирование
```

## Методы оценки

Все методы имеют единый интерфейс `score(text) → DetectorOutput(prob, sentences, signals, contributions)`
и дают одинаковый JSON.

**`features` (по умолчанию, CPU).** Интерпретируемая базовая модель (п. 4.1.3.5 ТЗ):
1. *Модель предложений*: логистическая регрессия на TF-IDF словесных (1–2) и символьных (2–4) n-грамм
   нормализованного текста. Оценка каждого предложения даёт локализацию фрагментов с символьными границами.
2. *Документная модель*: логистическая регрессия на 24 именованных признаках. Это агрегаты оценок предложений
   и стилометрия: вариативность длины предложений, лексическое разнообразие, пунктуация, формульные приветствия
   и концовки, шаблонные обороты генераторов, следы небрежного набора. Вклад признака равен произведению коэффициента
   на стандартизованное значение и выводится в объяснение (`feature_contributions`).
   На train оценки предложений считаются out-of-fold (GroupKFold), чтобы документная модель не переобучалась.

Перед извлечением признаков текст нормализуется: NFKC, удаление невидимых символов, унификация кавычек и тире,
замена URL, адресов и цифр на маркеры. Так модель не учится отличать «умные» кавычки генератора от ASCII-кавычек
старых писем.

**`lm`.** Пословный тэггер TNC-DBGC* (`src/model.py`). Используется `models/tnc_dbgc_llmtrace.pt` (после дообучения,
см. [ниже](#языковая-модель)) или исходный чекпоинт CoAT. Порог подбирается на val нашего датасета.

**`combined`.** `w_f · p_features + w_lm · p_lm`, веса задаются в `.env` (`DW1_WEIGHT_FEATURES`, `DW1_WEIGHT_LM`).

**Дополнительные сигналы письма:**
- *Утечка промпта.* В письме остались инструкции для LLM («=== Prompt brief ===», «Output only the HTML»,
  «Hard constraint: …»). Это прямое свидетельство генерации, поэтому индекс поднимается минимум до `DW1_PROMPT_LEAK_FLOOR` (0.9).
- *Маскировка* (скрытые элементы, символы нулевой ширины, подмена ссылок, формы с паролем) выводится в объяснение
  и JSON, но **в индекс не входит**: адаптивные легитимные рассылки тоже прячут блоки CSS-стилями, и это признак
  спама, а не генерации ИИ.
- *Изображения* (если включены): `index = (1 − w) · p_text + w · max(p_image)`, `w = DW1_WEIGHT_IMAGES`.

**Схема записи** (п. 4.1.2.4): `label` (0/1), `label_name` (human/ai/mixed), `generation_method`, `generator_model`,
`language`, `email_type` (corporate/marketing/text), `source`, `ai_zones`, `ai_char_intervals`, `group_id`, `split`.

близости TF-IDF ≥ 0.9. Пересечение групп между выборками проверяется при сборке.

**Состав v1** (после валидации и дедупликации; отбраковано 19 записей LLMTrace с интервалами вне текста,

## Метрики качества

`python evaluate.py --methods features` → `results/metrics/report.md`, `metrics_features.json`, `roc_features.png`.
Пороги подобраны на val: общий и отдельно для русского и английского (калибровочные параметры, п. 4.1.3.2), по правилу
«максимум F1 при FPR ≤ 0.20 на человеческих письмах и отдельно на рассылках». Тест для настройки не использовался.
Пороги задаются в настройках: `DW1_THRESHOLD`, `DW1_THRESHOLD_RU`, `DW1_THRESHOLD_EN` (п. 4.1.4.2). Если они не заданы,
берутся из `models/calibration.json` (сейчас en 0.332, ru 0.625).

### Сравнение методов на случайной подвыборке test (600 записей, seed 0)

LM на CPU работает примерно на порядок медленнее (≈0.1 с на текст против ≈0.01 с), поэтому `lm` и `combined` оценены на подвыборке. Пороги каждого метода (общий и по языкам) подобраны на val.

| Метрика | `features` | `lm` (дообученная) | `combined` (0.5 / 0.5) |
|---|---:|---:|---:|
| ROC-AUC | 0.908* | 0.911 | **0.935** |
| F1 | 0.857* | 0.878 | **0.881** |
| FPR (человек) | 0.167* | 0.188 | **0.092** |
| FPR (рассылки) | **0.021**\* | 0.241 ❌ | 0.138 |
| ROC-AUC частично сгенер. против человека | 0.832* | 0.850 | **0.870** |
| F1 локализации по символам | 0.718* | **0.838** | 0.824 |
| FPR на русском | 0.216* | 0.224 | **0.119** |
| Маскировка, мин. ROC-AUC | 0.895* | 0.807 | **0.896** |

\* полный test. Отчёты: `results/metrics/`, `results/metrics_lm/`, `results/metrics_combined/`.

**Вывод.** По умолчанию используется `features`: модель хранится в репозитории, работает на CPU и проходит все пороги
ТЗ. Лучший результат даёт `combined` (`DW1_METHOD=combined`), но ему нужны torch и веса LM (1.1 ГБ, [Google Диск](https://drive.google.com/file/d/1RK0uaD8Cj5EOmpgl_n12RwHSPhU-WU5M/view?usp=sharing)).

**Демо-письма в `samples/`** написаны вручную при разработке, это не реальная переписка. На них хорошо видны ограничения
метода `features` на коротких русских письмах:

| Письмо | `features` (порог ru 0.625) | `combined` (порог ru 0.581) |
|---|---|---|
| `ai_phishing_evasion.eml` (фишинг в стиле ИИ) | 0.54 — пропущено ❌ | 0.77 — ИИ ✅ |
| `legitimate_human.eml` (короткое деловое письмо) | 0.70 — ложное срабатывание ❌ | 0.83 — ложное срабатывание ❌ |

Отдельный порог для русского уменьшил долю ложных срабатываний на тесте (0.31 → 0.22), но часть ИИ-текстов теперь
пропускается. Для писем на русском лучше использовать `combined`.

  **отложенных кампаниях** (домены отправителей не пересекаются с train): **1.000 на 144 письмах**, но кампаний там немного.

## Языковая модель

Модель TNC-DBGC* (mDeBERTa-v3-base + Dynamic Dropout + BiGRU + CRF, `src/model.py`) ранее обучалась на корпусе
CoAT (перефразы и переводы генераторами прошлого поколения: ruGPT-3, mT5 и др.).

**Исходная модель на современных данных случайна.** ROC-AUC 0.497 на 500 записях теста предварительной сборки датасета
(та же методика, что и v1); на внешних наборах LLMTrace_classification 0.453 и SeqXGPT 0.450. Это и есть проблема
«модель обучена на старом датасете, F1 падает на современных».

**Дообучение** (`kaggle/finetune_llmtrace.ipynb`, Kaggle GPU T4, 76 мин): старт с чекпоинта CoAT, 20 000 документов
LLMTrace_detection (RU+EN), 2 эпохи; порог подобран на validation. Результаты на **полном test LLMTrace_detection
(13 588 текстов)**, `results/lm_kaggle/metrics.json`:

| Метрика | До (CoAT) | После дообучения |
|---|---:|---:|
| ROC-AUC (ИИ + смешанные против человека) | ≈ 0.45–0.50 | **0.907** (95% ДИ 0.902–0.912) |
| ROC-AUC, русский / английский | — | 0.922 / 0.894 |
| ROC-AUC, смешанные против человека | — | 0.851 |
| F1 / FPR при пороге с val | — | 0.870 / 0.238 (на val было 0.195) |
| F1 локализации по символам, смешанные тексты | — | 0.842 |

На нашем тесте писем дообученная LM даёт ROC-AUC 0.911 и F1 0.878 (таблица выше), но FPR на рассылках у неё 0.24, выше 0.20.
Совместно с методом на признаках (`combined`) проходят все пороги ТЗ: FPR 0.09, на рассылках 0.14, на русском 0.12.

**Веса `tnc_dbgc_llmtrace.pt` (1.1 ГБ)** в git не хранятся: [скачать с Google Диска](https://drive.google.com/file/d/1RK0uaD8Cj5EOmpgl_n12RwHSPhU-WU5M/view?usp=sharing) и положить в `models/`
(или перезапустить ноутбук). После этого доступны методы `lm` и `combined`: `DW1_METHOD=combined` или `--method combined`.

**Дообучение на современных генераторах.** Ноутбук `kaggle/finetune_llmtrace.ipynb` дообучает модель на LLMTrace_detection
(RU/EN, посимвольная разметка, ≈37 моделей 2023–2025 гг.) на бесплатном GPU Kaggle. Порог подбирается только на validation.
Инструкция: [`kaggle/README.md`](kaggle/README.md). После дообучения веса кладутся в `models/tnc_dbgc_llmtrace.pt`,
и `python evaluate.py --methods features,lm,combined` пересчитывает метрики на нашем тесте.

| | | lm | 300 | 0.635 [0.58; 0.69] | 0.534 | 0.153 |

  неполная, поэтому результат может быть оптимистичным.
- **Изображения.** Готовый детектор `umm-maybe/AI-image-detector` слабо работает на современных генераторах (Defactify:
  recall Midjourney v6 и SDXL 0.03). Поэтому анализ изображений выключен по умолчанию, а вес изображений в индексе небольшой (0.2).

## Ограничения

1. **Эпоха человеческих писем.** Единственный большой корпус писем, гарантированно написанных людьми, — Enron 2000–2002 гг.,
   а ИИ-письма современные. Модель может частично опираться на приметы эпохи, а не авторства. Что сделано: нормализация
   текста (кавычки, цифры, URL), генерация ИИ-писем на темы тех же писем Enron и отдельный срез «одна тема и эпоха»
   (ROC-AUC 0.881). **FPR на современных легитимных рассылках не измерен**: размеченных человеческих рассылок 2020-х у нас нет,
   а `samples_gray` по пояснению Заказчика содержит подозрительные комментарии.
2. **Русские письма.** Открытых русских писем, гарантированно написанных людьми, мы не нашли. Русский язык представлен
   текстами LLMTrace (новости, отзывы, вопросы и т. п.), а не письмами. С единым порогом FPR на русском у `features` был 0.31.
   Отдельные пороги по языкам (подобраны на val) снизили его до 0.22, у `combined` — 0.12.
3. **Правки одного предложения.** Если ИИ переписал одно предложение в человеческом письме, документная модель почти
   такое письмо не находит (recall 0–0.36). Высокие ROC-AUC частичной генерации и F1 локализации в основном получены
   на смешанных текстах LLMTrace, где ИИ-фрагменты длиннее.
4. **В test 73% записей из LLMTrace**, поэтому общие метрики сильно зависят от этого корпуса. Разрезы по источникам
   есть в `results/metrics/report.md`.
5. **Кейс Заказчика.** Метка «ИИ» взята из пояснения к данным. Письма сосредоточены в 38 кампаниях (в одной Klarna-подобной
   рассылке больше 200 писем). Отложенных кампаний мало, доверительный интервал recall широкий.
6. **LM и combined** оценены на подвыборке 600 записей теста. Веса LM в репозиторий не входят.
7. **Генерация** выполнена одной моделью (qwen2.5:7b, ограничение локального железа). Разнообразие генераторов дают 37 моделей LLMTrace.
8. **Маскировка** проверена простыми сценариями (zero-width, гомоглифы, опечатки, удаление формул). Перефразирование
   другой LLM не проверялось.
9. **Изображения**: качество детектора низкое (см. внешнюю валидацию).

## Установка и запуск

```bash
python3.12 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt            # метод на признаках, CLI, датасет, веб
pip install -r requirements-lm.txt         # опционально: языковая модель (torch, transformers)
pip install -r requirements-images.txt     # опционально: анализ изображений (OCR, детектор)
cp .env.example .env                       # настройки: метод, порог, веса, LLM
```

Обученная модель (`models/feature_model.json`, `models/calibration.json`) уже лежит в репозитории.

```bash
# одно письмо: индекс, вердикт, объяснение; полный JSON по запросу
python cli.py analyze --eml samples/ai_phishing_evasion.eml --output report.json
python cli.py analyze --text "Коллеги, напоминаю про отчёт до пятницы." --subject "Отчёт"
python cli.py analyze --html email.html --method combined

# каталог: JSON по каждому письму + сводный JSON; --resume для повторного запуска
python cli.py batch --dir path/to/emails --out-dir results/batch

# веб-интерфейс http://127.0.0.1:5000
uvicorn app:app --port 5000
```

Python API:
```python
from src.pipeline import EmailAnalysisPipeline
report = EmailAnalysisPipeline().analyze_email("letter.eml")
print(report.overall_ai_index, report.verdict)
print(report.to_json())

В каждое «ИИ-письмо» были вставлены скрытый текст или подменённые ссылки, а индекс складывался из штрафов за эти признаки. Проверялся детектор HTML-маскировки, а не генерации.
