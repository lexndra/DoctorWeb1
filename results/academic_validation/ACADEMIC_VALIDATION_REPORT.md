## 2. Методология

* **Случайная выборка с фиксированным seed = 42** (а не первые N строк потока). Способ выборки для каждого набора указан ниже.
* **Пороги выбраны априори.** Для метода `features` используется `doc_threshold` из `calibration.json`, подобранный на валидационной части *нашего* корпуса (ограничение FPR ≤ 20 %). Для `lm` — `doc_threshold` из `lm_calibration.json`, если он есть; если нет — фиксированный порог 0.5, помеченный как некалиброванный, и основной метрикой считается ROC-AUC. Для изображений — фиксированный порог 0.5 по вероятности метки `artificial`. **На данных бенчмарков ничего не подбиралось** (ни пороги, ни веса), переменная `DW1_THRESHOLD` скриптом игнорируется.
* Тексты длиннее 8000 символов обрезаются до первых 8000 символов (одинаково для всех методов).
* Все сторонние данные — только для оценки; в обучении `features` использовался собственный корпус (см. `training_params.json`), в который входит `iitolstykh/LLMTrace_detection` (другой набор тех же авторов, см. ниже).
* Данные бенчмарков не сохраняются на диск: SeqXGPT и LLMTrace читаются по HTTP в память; Defactify и NTIRE — выборочно (отдельные группы строк parquet / отдельные файлы zip-архива по HTTP-диапазонам).

* Метод `features`: порог 0.4902 — calibration.json: doc_threshold, подобран на собственном val (val). Сведения: `{"load_seconds": 0.2, "model_file": "models_dev/feature_model.json", "model": "features (TF-IDF sentence LR + stylometric document LR)", "dataset_version": "dev", "model_sha256": "4434328c676f9e2ed0a21b3cb68a013f07976cb248ba874b31306b5138980e4c", "last_seconds": 1.5, "own_val_metrics": {"roc_auc": 0.9263, "val_f1": 0.8626, "val_fpr_human": 0.154}}`
  * Для сравнения: ROC-AUC этого метода на *нашем* val (из файла калибровки) = 0.926.
* Метод `lm`: порог 0.4528 — lm_calibration.json: doc_threshold, подобран на собственном val (val). Сведения: `{"load_seconds": 10.3, "checkpoint": "tnc_dbgc_coat_best.pt", "device": "cpu", "last_seconds": 193.1, "own_val_metrics": {"roc_auc": 0.4554, "val_f1": 0.2959, "val_fpr_human": 0.1637}}`

## 3. Результаты и интерпретация по наборам

### 3.1 SeqXGPT (`TheItCrOw/SeqXGPT`)

**Что это за данные.** Англоязычный набор (все строки `lang = en-EN`), единственный сплит `train`, 38 304 текста: 6 400 человеческих и ≈31 900 сгенерированных моделями GPT-2, GPT-J, GPT-Neo, LLaMA и GPT-3 (`gpt3re`). Источник — SeqXGPT-Bench и связанные с ним наборы (поле `source`). Это не письма; генераторы — относительно старые модели 2019–2023 гг.

**Выборка.** весь файл TheItCrOw/SeqXGPT (38304 строк, 33 МБ, единственный сплит train) прочитан по HTTP в память; простая случайная выборка без возвращения seed=42: 150 human + 150 ai (поровну по 5 генераторам).

**Наблюдение о составе (факт, измерено скриптом):** у 92 % ИИ-текстов первые 80 символов совпадают с началом какого-либо человеческого текста набора. Т. е. значительная часть «ИИ»-документов, по-видимому, начинается с человеческого фрагмента и продолжена моделью (в SeqXGPT-Bench изначально решалась задача разметки на уровне предложений). Документная метка `ai` в таком случае означает «содержит ИИ-фрагмент».

* `features`: ROC-AUC 0.592 — различение выше случайного, но слабое; при пороге 0.4902: precision 0.658, recall 0.320, F1 0.430, FPR 0.167.
  Recall по генераторам: gpt2 0.13, gpt3re 0.93, gptj 0.13, gptneo 0.20, llama 0.20.
* `lm`: ROC-AUC 0.450 — статистически **не отличается от случайного** (95 % ДИ содержит 0.5); при пороге 0.4528: precision 0.484, recall 0.293, F1 0.365, FPR 0.313 — FPR выше ограничения 20 %, заданного при калибровке на нашем val.
  Recall по генераторам: gpt2 0.20, gpt3re 0.07, gptj 0.33, gptneo 0.40, llama 0.47.

Требование ТЗ — работа с RU и EN текстами, поэтому английский набор является обязательной, а не «посторонней» проверкой. Модель `lm` построена на mDeBERTa-v3 — многоязычной модели; `razdel` используется только для разбиения на слова/предложения и не делает модель русскоязычной.

*Гипотезы (не проверялись):* (а) смешанные человек+ИИ документы снижают документную оценку; (б) стиль старых генераторов (GPT-2/Neo/J) отличается от современных LLM, на которых строился наш корпус; (в) научные аннотации и отзывы — далёкий от писем домен.

### 3.4 NTIRE (`deepfakesMSU/NTIRE-RobustAIGenDetection-train`)

**Что это за данные.** Обучающая часть соревнования NTIRE 2026 «Robust AI-Generated Image Detection in the Wild» (CVPR 2026 Workshops; организаторы — лаборатория МГУ). ≈277 тыс. реальных и сгенерированных изображений с дополнительными «in-the-wild» преобразованиями (кадрирование, масштабирование, сжатие, размытие); 6 zip-шардов по ~50 тыс., по README распределение в шардах одинаковое; разметка — `labels.csv` (0 — реальное, 1 — сгенерированное), сведений о генераторе для каждого изображения нет.

**Доступ.** В предыдущей версии отчёта набор числился закрытым (gated, «нужен HF-токен»). На момент данного запуска Hugging Face API сообщает `gated = False`, файлы прочитаны без токена.

**Выборка.** архивы не скачиваются целиком (6 zip по 11–21 ГБ): случайно (seed=42) выбран shard_0.zip, по HTTP прочитаны его оглавление и labels.csv (50000 изображений), затем простая случайная выборка 150 реальных + 150 сгенерированных; загружено ≈112 МБ, только в памяти. Состав шарда: `{"0": 17982, "1": 32018}`.

* ROC-AUC 0.715 — умеренное различение; при пороге 0.5: precision 0.719, recall 0.460, F1 0.561, FPR 0.180.

*Гипотеза (не проверялась):* преобразования «in-the-wild» (сжатие, размытие, ресайз) специально задуманы организаторами как помеха для детекторов и могут влиять на результат классификатора.

## 4. Ограничения

* Небольшие выборки (сотни объектов): доверительные интервалы ROC-AUC широкие, различия в пределах ДИ не следует интерпретировать.
* Ни один из наборов не состоит из электронных писем; это проверка переносимости на чужие домены, а не оценка в целевом сценарии.
* LLMTrace_classification может пересекаться по темам/источникам с LLMTrace_detection, использованным в обучении.
* Метрики при пороге зависят от того, насколько распределение оценок на чужом домене совпадает с нашим val; мы сознательно не перекалибровываем порог, чтобы не допустить утечки.
